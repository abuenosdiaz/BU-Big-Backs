Kiro IDE was used heavily to design the backend of our application. Our backend designers employed spec-driven development by first discussing with one another what features were necessary to make the frontend functional. After obtaining the API key to access our dataset, we employed Kiro to perform an explicit series of actions (described in more detail on the following pages) which included downloading the data, accessing it as a DataFrame, analyzing the data, and integrating it into the frontend by creating our own API. Beyond priming the Kiro application to suit our program to best fit its future needs, this spec-driven approach ensured that the backend designers both had clear, achievable goals to work towards at all times. Specifically, one of our team members focused on the creation of DataFrames from JSON files and general data analysis, while the other teammate who was focused on the backend created the system to download data from the Boston University API for our dataset and create our own API to connect the frontend. Overall, we had significantly more structure in our workflow due to the use of spec-driven development.

Steering was used as boundaries and assumptions were built over the span of the conversation. Kiro was used to create a file titled project-conventions within the steering folder to describe the expectations established for one of our backend developers. These included certain means of avoiding bias in data and verifying full system functionality as effectively as realistically can be done before finalizing a suggested change. Property-Based Texting was employed when verifying the integrity of the data outputted by the algorithm in several ways. It was ensured that none of the percentage values exceeded 100 or fell below 0, as this would indicate a clear issue. Furthermore, the entries in the Pandas DataFrame were compared to the actual entries on the dining hall websites to ensure that the information consistently matched the expected values.



Kiro was used in an iterative fashion to add the following backend features:
Downloading the relevant data to our server
Our data was present in Boston University’s API. The API contained information from the current day to seven days in the future. We used Kiro to access this API information through the web and create corresponding JSON files within our Github environment. Now, the data can be added through the program rather than through a manual file transfer.

Creating DataFrames from the JSON files
After the JSON files were created, the next step was to create a DataFrame which stores all of the dining information. This was completed by prompting Kiro, which employed a system of nested loops to convert the JSON information. It was noticed that the meals in the JSON file were formatted as one category (meal) containing subcategories (station) containing subcategories (food item). Exploiting this format, Kiro implemented a triple loop which iterates through each category, reaching each food item and assigning the relevant information.

Data Analysis
Kiro was used to analyze the data from the datasets, creating a new DataFrame with columns including trends in the rise or fall of vegan options, overall percentages of options with food restrictions, and the average calories of all of the meals. From this Kiro implementation, we discovered that there are some lackluster aspects of the menu setup. For example, 7.818% of items are labeled as gluten free for the upcoming week at Warren Towers, but only 2.901% of items are labeled gluten free at Marciano Commons. This does not necessarily indicate that gluten free items are this scarce, but simply suggests that the BU labels should be updated to reflect the dietary restrictions they contain. This is exemplified by entries such as “Corn on the Cob” on 10/24/2026, which is labeled as vegan, vegetarian, and halal, but not gluten free despite this being the case.

Integrating the Backend and the Frontend
Kiro was used to create an API to allow for cooperation between the frontend and backend of the system. The DataFrame files were used to establish a Python backend which is capable of communicating with the frontend. It was also used to create a server.py which carries the DataFrames to the frontend. It also was used to create API.md which contains a series of references to ensure that the Kiro instances running for different users can reference the same files.
